# Threat Propagation Chain Template

该模板定义间接工具指令注入威胁传播链路的基础结构。预测过程必须优先遵循本模板，再结合 `graph_wo_check.md`、`SKILL.md` 和第一阶段威胁分析结果生成具体传播链。

## Chain Goal

传播链描述的是攻击过程，不是正常业务流程。

- 起点必须是被攻击的工具、节点或能力，不得从正常 workflow 的 start node 开始。
- 链路应解释威胁如何从不可信输入进入工具输出，再被后续节点当作可信上下文、数据或指令消费。
- 链路必须以安全影响、风险被控制住、或传播无法继续作为结束条件。

## Required Node Types

每条传播链至少考虑以下节点类型：

- `attacked_tool`: 被攻击工具或起始节点。描述不可信内容、污染指令或恶意状态进入的位置。
- `tainted_output`: 被污染输出生成节点。描述工具把非可信内容转成后续可消费结果的过程。
- `trust_boundary_crossing`: 信任边界跨越节点。描述污染内容从外部/低信任域进入内部/高信任域的转换。
- `instruction_interpretation`: 指令解释节点。描述后续工具或模型把污染内容误当作任务指令、参数、策略或约束。
- `privileged_action`: 高影响动作节点。描述可能触发敏感读写、外部调用、权限动作、记忆写入或状态改变的位置。
- `impact_or_containment`: 影响或控制节点。描述最终造成的安全影响，或被校验、隔离、人工确认等机制阻断。
- `result_output`: 结果输出节点。描述污染内容通过工作流出口直接返回给用户或下游系统的位置，可能导致错误信息传播或误导。
- `no_attack_path`: 无攻击路径节点。当威胁分析确认不存在间接工具指令注入攻击向量时，作为传播链的唯一节点，表示传播链为空。
- `url_generation_node`: URL生成节点。描述根据用户输入或上下文动态生成目标URL的位置，可能被恶意输入诱导生成指向非预期或恶意页面的URL。
- `data_extraction_node`: 数据提取节点。描述从不可信数据源（如网页DOM、文件内容、API响应）中提取结构化数据的节点，可能将污染内容引入后续处理流程。
- `decision_node`: 决策节点。描述根据输入或上下文做出分支选择（如任务类型识别、鉴权需求判断、路由选择）的节点，可能被污染指令误导导致错误决策。
- `cache_node`: 缓存节点。描述将数据写入本地或远程缓存（如文件、数据库、内存）的节点，污染内容可能通过缓存持久化并影响后续相同或不同用户的请求。
- `cache_read_node`: 缓存读取节点。描述从缓存中读取数据的节点，可能将之前存储的污染内容重新引入工作流，导致延迟传播或跨请求污染。
- `input_validation_node`: 输入校验节点。描述对用户输入、文件内容、API响应等外部数据进行格式、大小、模式或类型校验的节点，可能阻断污染内容进入后续处理流程。
- `iteration_loop_node`: 迭代循环节点。描述工作流中存在循环执行路径（如重试、迭代优化、质量反馈循环）的节点，污染内容可能通过循环路径多次传播，形成闭环攻击。
- `quality_evaluation_node`: 质量评估节点。描述对执行结果进行质量评分或正确性判断的节点，可能被污染内容误导产生错误评分，影响后续决策。
- `retry_generation_node`: 重试生成节点。描述基于失败步骤或质量评分生成改进步骤参数的节点，可能将污染内容转化为新的恶意指令。
- `file_read_node`: 文件读取节点。描述从文件系统读取外部文件（如配置文件、参考文档、上下文文件）的节点，可能将文件中的污染内容引入工作流。
- `code_generation_node`: 代码生成节点。描述基于输入或上下文生成可执行代码（如JavaScript、配置代码、SQL）的节点，可能将污染内容转化为恶意代码。
- `validation_node`: 验证节点。描述对生成结果进行正确性、安全性或合规性验证的节点，可能因验证逻辑不完善而无法检测污染内容。
- `script_execution_node`: 脚本执行节点。描述基于输入或上下文执行外部脚本（如Python、Shell、批处理文件）的节点，可能将污染内容转化为恶意指令被脚本解释执行，导致工具误用或代码执行。
- `fallback_node`: 回退节点。描述在操作失败或异常时执行回退逻辑（如重试、降级、默认值返回）的节点，可能将污染上下文通过回退路径重新引入工作流，形成循环传播。

如果某条链没有对应节点，应在 `reason` 中说明为什么跳过该节点类型。

## Propagation Logic Gates

传播链中应显式考虑以下逻辑门。逻辑门可以表现为 path 节点，也可以表现为 edge 的 `propagation_mechanism`。

- `untrusted_input_gate`: 输入是否来自外部网页、文件、邮件、API 响应、搜索结果、日志、记忆或用户可控内容。
- `sanitization_gate`: 是否经过清洗、引用、转义、结构化解析或指令/数据分离。
- `trust_promotion_gate`: 污染内容是否被提升为可信上下文、系统约束、工具参数、执行计划或后续 prompt。
- `permission_gate`: 后续节点是否拥有更高权限、更大访问范围、更强执行能力或更敏感的数据视野。
- `state_persistence_gate`: 污染内容是否写入记忆、缓存、文件、数据库、配置或长期状态。
- `external_effect_gate`: 是否会产生外部可见影响，例如发消息、写文件、调用 API、提交交易、改配置或泄露数据。
- `containment_gate`: 是否存在人工确认、最小权限、allowlist、schema 校验、来源标记、审计日志或失败回滚。
- `output_propagation_gate`: 污染内容是否通过工作流出口直接输出给用户或下游系统，导致错误信息传播或误导。
- `no_external_data_source_gate`: 无外部数据源门。当工作流中所有节点仅处理用户请求和内部权限检查结果，未引入外部网页、搜索结果、文件内容、API 响应、邮件/消息、记忆、数据库、日志或模型输出等不可信数据源时，该门阻断传播链。
- `url_validation_gate`: URL验证门。描述目标URL是否经过域名白名单、路径限制、协议校验或格式验证，防止恶意URL被加载。
- `data_content_validation_gate`: 数据内容验证门。描述提取的数据是否经过字段类型、长度、格式或内容模式校验，防止污染数据进入后续处理。
- `decision_integrity_gate`: 决策完整性门。描述决策节点（如任务类型识别、鉴权判断、路由选择）的输入是否经过校验、白名单匹配或上下文验证，防止被污染指令误导导致错误分支选择。
- `cache_integrity_gate`: 缓存完整性门。描述缓存数据是否经过签名、哈希校验、版本控制或定期清理，防止污染缓存内容被长期存储并影响后续请求。
- `cache_hit_gate`: 缓存命中门。描述缓存命中时是否对返回数据执行额外的校验（如内容格式验证、来源标记检查），防止污染缓存数据直接进入后续处理。
- `input_format_validation_gate`: 输入格式校验门。描述用户输入、文件内容或API响应是否经过格式、大小、类型或模式校验，防止不符合预期的数据进入后续处理流程。
- `iteration_loop_gate`: 迭代循环门。描述工作流中是否存在循环执行路径（如重试、迭代优化、质量反馈循环），污染内容可能通过循环路径多次传播，形成闭环攻击。
- `quality_evaluation_gate`: 质量评估门。描述质量评估逻辑是否基于外部内容或工具输出进行判断，污染内容可能操控评分结果，影响迭代决策。
- `retry_parameter_gate`: 重试参数门。描述重试节点生成的步骤参数是否经过重新校验（如白名单、危险操作检测），防止污染内容通过重试路径生成新的恶意指令。
- `file_integrity_gate`: 文件完整性门。描述文件读取节点是否对文件内容进行完整性校验（如哈希验证、数字签名、只读权限检查），防止被篡改的文件内容进入工作流。
- `code_safety_gate`: 代码安全门。描述代码生成节点是否对生成的代码进行静态分析、沙箱执行或危险模式检测，防止恶意代码被输出或部署。
- `validation_effectiveness_gate`: 验证有效性门。描述验证节点是否具备检测污染内容的能力（如模式匹配、异常检测、白名单校验），防止验证节点被污染内容绕过。
- `script_safety_gate`: 脚本安全门。描述脚本执行节点是否对输入参数进行消毒、使用沙箱环境、限制执行权限或对脚本输出进行安全检查，防止恶意指令被脚本解释执行导致工具误用或代码执行。
- `fallback_loop_gate`: 回退循环门。描述工作流中是否存在通过回退节点（如重试、降级、默认值返回）将污染上下文重新引入上游节点的循环路径，污染内容可能通过回退路径形成闭环传播，导致重复执行或无限循环。

## Impact Reasoning

达成影响时应至少从以下维度判断：

- `confidentiality`: 是否可能导致敏感信息、凭据、隐私数据、内部上下文或系统提示泄露。
- `integrity`: 是否可能导致结果被篡改、工具参数被污染、工作流决策错误、状态被写入错误内容。
- `availability`: 是否可能导致循环调用、资源耗尽、任务阻塞、错误重试、成本异常或服务不可用。
- `authority`: 是否可能导致越权调用、权限边界扩大、非预期外部动作或高权限工具被间接驱动。
- `business`: 是否可能导致交易损失、错误通知、合规风险、品牌/用户信任损害或错误决策。
- `propagation_delay`: 是否可能导致污染内容通过缓存、记忆或持久化存储延迟传播，影响后续不同用户或不同时间点的请求。
- `loop_amplification`: 是否可能导致污染内容通过迭代循环路径多次传播，每次循环放大攻击效果或扩大影响范围。
- `supply_chain`: 是否可能导致通过篡改外部文件（如配置文件、参考文档、上下文文件）污染工作流，影响下游用户或系统。
- `tool_misuse`: 是否可能导致外部脚本被恶意指令操控，执行非预期操作（如篡改结果、泄露数据、执行任意代码），造成工具误用或权限滥用。
- `resource_exhaustion`: 是否可能导致通过循环传播、重复执行或无限重试消耗系统资源（如CPU、内存、网络带宽、API配额），造成拒绝服务或成本异常。

## Chain Writing Requirements

每条链必须满足：

- `starting_attack_point` 和 `path[0]` 指向同一个被攻击工具或节点。
- `path` 按攻击传播顺序组织，而不是按正常任务完整流程组织。
- 每个 `path` 节点必须说明当前威胁状态和传播/停止原因。
- 每条 `edges` 必须说明污染内容、指令、权限上下文、状态或敏感信息如何移动。
- `impact.summary` 必须明确说明最终影响或被控制住的结果。
- 风险等级应综合攻击面、权限、数据敏感性、可达性、缓解机制和影响范围判断。
- 当威胁分析确认不存在间接工具指令注入攻击向量时，传播链应包含一个 `no_attack_path` 节点，并在 `impact.summary` 中说明无可行攻击路径的原因。
